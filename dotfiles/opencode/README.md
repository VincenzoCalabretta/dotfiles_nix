# OpenCode with the local llama.cpp server

`~/.config/opencode/opencode.json` is generated by `modules/opencode.nix`,
not checked in as a static file. That module builds two flake inputs -
[`llama-server`](ssh://git@10.10.0.101/v/llama-server.git) (the Qwen3-30B-A3B
server) and [`opencode-mcp-tools`](ssh://git@10.10.0.101/v/opencode-mcp-tools.git)
(web search + code-search + test-runner + structured-output MCP servers, plus
SearXNG) - and writes their real Nix store paths straight into the config's
`mcp` block. A plain `home-manager switch --flake ~/dotfiles-nix` on any
machine that can reach that Forgejo instance (same LAN, or over the
`wireguard` module) is enough to deploy the whole thing; no sibling
`~/projects` checkout or manual cloning required.

The model defaults to `llama.cpp/qwen3-30b-a3b-instruct-2507`, talking to the
OpenAI-compatible endpoint at `http://127.0.0.1:8080/v1` - no API key needed.
If the server moves to another host/port, edit `provider."llama.cpp".options.baseURL`
in `modules/opencode.nix` (keep the `/v1` suffix).

## Starting things up

Both the model server and the SearXNG instance backing `mcp_search` are
installed as **on-demand** systemd user services - deliberately not enabled
at login, since the 30B model reserves most of an 8GB laptop GPU's VRAM
whether or not you end up using opencode that session:

```sh
systemctl --user start llama-server
systemctl --user start opencode-searxng   # only needed for web search
opencode
```

`opencode mcp list` should show all four MCP servers (`search`, `code-search`,
`test-runner`, `grammar`) as connected regardless of whether SearXNG/llama-server
are running yet - only the tool calls that actually hit them will fail until
you start those two services.

## Redeploying on a new machine

1. Install Nix (flakes enabled) and make sure the machine has the SSH key
   for `git@10.10.0.101` (Forgejo) and can reach it.
2. `home-manager switch --flake ~/dotfiles-nix` (after cloning this repo) -
   this fetches `llama-server` and `opencode-mcp-tools` from Forgejo and
   builds everything.
3. If the new machine's GPU isn't an Ada-class card (compute capability 8.9),
   edit `cudaCapabilities` in the `llama-server` repo's `flake.nix` to match
   (`nvidia-smi --query-gpu=compute_cap --format=csv`), and re-check the
   `--n-cpu-moe`/`--ctx-size`/KV-cache-quant flags there, which were tuned
   for an 8GB VRAM budget.
4. `systemctl --user start llama-server opencode-searxng`, then `opencode`.
